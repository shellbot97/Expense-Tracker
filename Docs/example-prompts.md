### Pro-Tips for your Workflow:

* **Memory Injection:** When you copy-paste the `project_state.json` in the "Golden Prompt," you are essentially "bootstrapping" the model's brain. If the project gets huge (e.g., 50+ files), ask the model to create a `summary.md` of the core logic and include that instead of the entire file list to save tokens.
* **The "Rulebook" Rule:** If you decide to change a coding standard (e.g., switching from `if err != nil` patterns in Go to a different error handler), ensure you update `README_DEV.md` immediately so the model stays aligned.
* **Edge Case Focus:** Since this handles financial data, explicitly tell the model in your "Golden Prompt": *"Prioritize precision for currency calculations (use fixed-point arithmetic, not floats) and ensure data integrity for uploads."*

### Prompt for Frontend Development

**Hello! Your task is to build a modern, responsive, and user-friendly frontend for an Expense Tracking System.**

The backend for this application is being developed in parallel. Your primary goal is to create the user interface and connect it to the backend API as it becomes available.

**1. Understand the Backend:**

The backend is a Python FastAPI application. The most critical piece of information for you is the OpenAPI specification, which documents all available API endpoints, their request/response structures, and data models.

*   **API Specification:** The live, machine-readable API documentation is generated by the backend and is available at `http://127.0.0.1:8000/openapi.json`.
*   **Interactive API Docs:** You can explore the API interactively using Swagger UI at `http://127.0.0.1:8000/docs`.

**Your first step is always to fetch and analyze the `openapi.json` file to understand what backend features are ready for integration.**

**2. Core Application Features:**

Based on the backend, you will need to implement UI for the following features:

*   **User Authentication:**
    *   User registration page.
    *   User login page.
    *   A mechanism to store and use the authentication token for subsequent API requests.
    *   User logout functionality.
*   **Dashboard:**
    *   An overview of recent transactions.
    *   Summary of spending by category.
    *   Budget status overview.
*   **Transactions Management:**
    *   A view to list all transactions with filtering and sorting options (by date, category, etc.).
    *   A form to add a new transaction (amount, description, category, source).
    *   Functionality to edit or delete existing transactions.
*   **Categories, Sources, and Budgets:**
    *   Separate sections to manage (Create, Read, Update, Delete) spending categories, income sources, and budgets.

**3. Suggested Technology Stack:**

Unless specified otherwise, please use a modern and robust technology stack. I recommend:

*   **Framework:** React or Vue.js
*   **Language:** TypeScript
*   **Styling:** Tailwind CSS for a utility-first approach or a component library like Material-UI/Chakra UI.
*   **State Management:** A suitable library like Redux Toolkit (for React) or Pinia (for Vue).
*   **API Client:** `axios` or `fetch` for making API calls.

**4. Your Development Workflow (The "Automatic Integration" Process):**

To stay synchronized with the backend development, you must follow this iterative workflow:

1.  **Check for Backend Updates:** At the beginning of each work session, read the backend's `openapi.json` file. Compare it to the version you last worked with to identify new or changed API endpoints.
2.  **Plan Your Work:** Based on the newly available endpoints, create a plan. For example, if you see a new `POST /transactions` endpoint, your plan should be to build the "Add New Transaction" form.
3.  **Implement the UI:** Build the necessary UI components for the feature.
4.  **Integrate the API:** Connect your new UI components to the corresponding backend API endpoints.
5.  **Test and Verify:** Ensure the feature works correctly from end to end.
6.  **Repeat:** Await the next set of backend updates and repeat the process.

By consistently referring to the `openapi.json` specification as the "source of truth," you will effectively integrate backend work as it is completed.

**Please begin by setting up the initial project structure for the frontend and then perform your first check of the backend's `openapi.json` to plan your work.**
